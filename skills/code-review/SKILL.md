# Code Review Skill

当用户请求代码审查时，按照以下流程执行。

## 输入

- `git.diff` — 待审查的代码变更（来自 git diff）

## 审查维度

1. **安全性**：SQL 注入、XSS、命令注入、敏感信息泄露、不安全的反序列化
2. **性能**：不必要的循环、N+1 查询、内存泄漏风险、大对象复制
3. **可维护性**：命名、重复代码、魔法数字、复杂度过高
4. **最佳实践**：错误处理、边界条件、资源释放、类型安全

## 审查流程

1. 分析 `git.diff` 中的变更
2. 逐维度给出发现的问题，标注严重程度（High / Medium / Low）
3. 为每个问题给出具体的修复建议和示例代码

## Output Format

```
## 代码审查报告

### 变更概览
- 变更文件数 / 新增行数 / 删除行数

### 发现的问题
| 严重程度 | 文件 | 行号 | 问题描述 | 修复建议 |
|----------|------|------|----------|----------|

### 总结
- 总体评价
- 优先修复项（High 优先）
```
